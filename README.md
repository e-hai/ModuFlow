## 📖 平台定位与设计理念

传统多智能体系统（Multi-Agent System）在实际落地中常面临**智能体过度放权导致的失控**、**调用在线大模型导致 API 账单爆雷**、以及**缺少确定性风控与止损机制**等致命痛点。

**ModuFlow** 通过创新的 **「三层架构」**、**「11 道标准产研工序」**、**「关口分级模型 (🟢/🟡/🔴)」** 与 **「确定性安全熔断器 (Zero-LLM Circuit Breaker)」**，构建人机紧密协同、权责边界分明、商业单位经济学严格闭环的 AI 原生产研与运营操作系统。

## 🏛️ 三层架构体系 (Three-Tier Architecture)

ModuFlow 严格实施 **「人类战略层 → 项目总控层 (Lead) → 专业执行层」** 三层架构体系：

```
                    ┌────────────────────────────────────────┐
                    │      人类战略层 (Human Strategic Tier)    │
                    │  • 立项与关闭决策    • 投资组合与资金调配  │
                    │  • 授权包 (YAML)   • 红级关口 (🔴 审批) │
                    │  • 商店/生产凭证持有  • 放权模式控制 (建议/推进)│
                    └───────────────────┬────────────────────┘
                                        │ 注入只读 authorization.yaml
                                        ▼
                    ┌────────────────────────────────────────┐
                    │       项目总控层 (Project Tier / Lead)   │
                    │  • 工序调度与派活    • 交付物交接校验       │
                    │  • 低风险 CR 仲裁   • 整理关口申请单与日报 │
                    │  • 协作模式研判建议  • 受 6 大硬红线严密约束│
                    └───────────────────┬────────────────────┘
                                        │ 调度分配与工序推进
                                        ▼
    ┌────────────────────────────────────────────────────────────────────────┐
    │                 专业执行层 (Execution Tier / 9 大专业 Agent)            │
    │  [mr 市场研究]   [ba 商业分析]   [pm 产品经理]   [mkt 增长营销]  [ux 设计用研]  │
    │  [eng 研发架构]  [qa 测试保障]   [ops 数据运营]  [cmp 合规风控]                 │
    │  • 物理隔离工作区   • 动态挂载专属 Skill/MCP   • 权限拦截器实时防护        │
    └────────────────────────────────────────────────────────────────────────┘
```

1. **人类战略层 (Human Strategic Tier)**：
   - 拥有绝对核心权力：项目立项/终止、总体预算注资、硬止损线设定、商店生产凭证持有、重大红级关口审批。
   - 任何 Agent（包括 Lead）绝不可修改授权包、批准预算上调或越权签发凭证。
2. **项目总控层 (Project Tier / `lead`)**：
   - 每个产品具备独立团队实例，由 `lead` 统一调度编排与监督交付质量。
   - 提供「AI 仅提建议」与「AI 自动推进」双模式切换，协助人类进行常规低风险工序推进，自动追踪建议与人类裁决一致率。
3. **专业执行层 (Execution Tier / 9 大专业 Agent)**：
   - 9 大角色独立物理工作区隔离，严格遵循输入输出契约与红线禁区，动态挂载专属 Skill 与 MCP 工具箱。

## ⚡ 标准产研 11 道核心工序与关口分级模型

### 1. 11 道标准产研工序全景

```
[01 市场研究] ──> [02 商业模式分析] ──> [03 产品方向决策] ──> [04 低成本假门验证] ──> [05 产品需求定义]
                                                                                               │
   ┌───────────────────────────────────────────────────────────────────────────────────────────┘
   ▼
[06 设计实现] ──> [07 开发实现] ──> [08 测试与 QA] ──> [09 发布与上线] ──> [10 市场推广与获客] ──> [11 运营分析与持续迭代]
```

### 2. 关口分级模型 (🟢 / 🟡 / 🔴)

- 🟢 **绿级 (Green)**：低风险工序，在「AI 自动推进」模式下可由系统自动核验放行，事后审计留痕。
- 🟡 **黄级 (Yellow)**：方向性决策，由系统汇总一页纸关口申请单，推入人类待办批量确认。
- 🔴 **红级 (Red)**：重大决策节点，系统**代码级物理阻断**后续流转，必须由人类负责人亲自签署放行。

| 工序编号与名称 | 关口代号 | 级别 | 审批放行人 | 核心放行条件与红线 |
| :--- | :---: | :---: | :---: | :--- |
| **`01 市场研究`** | 赛道门禁 | 🟢 | `lead` | 包含自下而上 SOM 现实测算，明确“干/不干/怎么干”建议。 |
| **`02 商业模式`** | LTV/CAC | 🟡 | 人类审批 | LTV/CAC 预测值 $\ge 3.0$ 且回本周期在预算内；`ba` 是商业定价唯一权力来源。 |
| **`03 方向决策`** | **G1 立项** | 🟡 | 人类审批 | 输出一页纸精益方向卡；合规 Agent (`cmp`) 初筛通过无红灯。 |
| **`04 假门验证`** | **G2 外测** | 🟡 | 人类审批 | 单文件移动端 H5 真实着陆页；外测数据严禁凭空虚构，触碰止损线自动暂停。 |
| **`05 需求定义`** | prd_linter | 🟢 | `lead` | 纯业务 PRD 契约（**严禁编写建表 DDL**）；**涉及内购支付或隐私时自动升为 🔴**。 |
| **`06 设计实现`** | HIG / M3 | 🟢 | `lead` | 依据平台自动执行 iOS HIG（灵动岛 $\ge 71\text{pt}$、触控 $\ge 44\text{pt}$）或 Android M3 审计。 |
| **`07 开发实现`** | 零推理审计 | 🟢 | `lead` | 单测覆盖率 $\ge 80\%$；代码浏览器支持与本地 Android Studio / Xcode 原生调起；**纯客户端项目客户端在线 AI 调用必须为 0**（严控边际成本）。 |
| **`08 测试 QA`** | **G3 质量门** | 🟢 | `qa` | P0/P1 阻塞缺陷全部清零；行使质量一票否决权。 |
| **`09 发布上线`** | **G4 提审发布** | 🔴 | **人类必批** | **绝对硬红线：必须有人类确认记录方可提审**！具备合规审查、降级开关与回滚预案。 |
| **`10 推广获客`** | 买量门禁 | 🟡 | 人类审批 | 首次买量投放或开辟新国家市场审批；eCAC 超标自动熔断。 |
| **`11 运营迭代`** | Backlog 评审 | 🟢 | `lead` | 形成 V1.1 需求建议书推入工序 05；重大改版升为 🟡。 |
| **`紧急热修`** | P0 热修关口 | 🔴 | **人类必批** | 预授权降级回滚；上线后 24 小时内必须补齐复盘、单测与 PRD 更新。 |

## 🤖 10 大专业 Agent 角色分工与红线边界

| 角色 | 代码 | 核心定位与职责 | 绝对禁区 (Redlines) |
| :--- | :---: | :--- | :--- |
| **项目总控** | `lead` | 全局工序调度、交接完整性审计、低风险 CR 仲裁、整理每日简报 | 严禁自批黄/红关口；严禁修改预算与授权包；严禁提交应用商店审核 |
| **市场研究** | `mr` | 出海赛道摸底、SOM 精算、用户画像 (JTBD)、竞品差评软肋分析 | 严禁宏观务虚；严禁越界设计功能规格与套餐价格 |
| **商业分析** | `ba` | 变现阶梯设计、单位经济 (Unit Economics) 精算、**全平台价格唯一来源** | 严禁虚高假设；严禁编写支付 SDK 代码；其他角色严禁篡改其确定的定价 |
| **产品经理** | `pm` | 精益方向假设（工序 03）、纯业务 PRD 规格契约（工序 05） | **严守业务本位，严禁编写 SQL DDL、数据库索引或代码级接口**（归属研发） |
| **增长营销** | `mkt` | 低成本可交互 H5 假门验证原型建造、冷启动获客与 ASO | 严禁凭空编造外测转化数据；严禁构建服务端数据库或生产后端 |
| **设计用研** | `ux` | Apple HIG / Android M3 体验守护、Design Tokens、高保真原型交付 | 严禁私自魔改业务流程（必须提 CR）；严禁违反平台硬件安全区 |
| **研发架构** | `eng` | 物理数据模型（DDL/索引）、核心逻辑代码交付、单元测试保障 | 严禁私自阉割产品功能；**纯客户端 Profile 下严禁引入客户端在线推理** |
| **测试保障** | `qa` | 端到端用例执行、缺陷管理矩阵、G3 质量门准出、G4 提审合规检查 | 存在 P0/P1 Bug 时强制阻断发布；严禁越权放行；严禁直接修改业务代码 |
| **数据运营** | `ops` | 全生命周期数据复盘、留存衰减漏斗诊断、下一版本 Backlog 发起 | 严禁越界修改线上代码；严禁伪需求膨胀；严禁绕过工序 05 直接开工 |
| **合规风控** | `cmp` | 全球法律合规审查、隐私数据流审计 (GDPR/CCPA)、平台政策防下架 | 发现重大违规直接触发 **G5 关口自动升级**，一票否决违规上线 |

## 🛡️ 确定性安全与参数化控制 (Zero-LLM Circuit Breaker)

- **授权包规范 (`authorization.yaml`)**：
  每个产品立项必须拥有合规的授权包，定义预算上限、分阶段配额、硬止损线 (`hard_stop_loss_usd`)、交付时限与 6 项必选禁止行为。
- **操作系统级只读防护 (`0o444`)**：
  授权包、平台规范与角色系统提示词在操作系统层面设为只读，底层安全防护层 (`security_guard.py`) 实时物理拦截任何 Agent 的写入企图并记入审计日志。
- **项目 Profile 参数化驱动**：
  - **`platform: ios | android`**：iOS 项目自动匹配 HIG 规范校验（灵动岛/刘海顶部 $\ge 71\text{pt}$、触控热区 $\ge 44\text{pt}$、Apple 4.3 查重）；Android 项目自动匹配 Material 3 规范校验，**杜绝全局一刀切**。
  - **`client_zero_inference: bool`**：工具类产品死守“客户端零在线推理成本”红线，AI 资产离线预处理，保障 $90\%+$ 高毛利；端侧友好型项目则允许 CoreML / ONNX 端侧轻量运算。
- **物理工作区纯 ASCII 规范与无空格目录隔离**：
  文件系统物理工作区严格遵循 `run_{slug}/{order_index}_{slug}` 命名准则（如 `07_development`），彻底根除 Android AAPT2、Gradle daemon、Xcode LLDB/SPM 在含中文或空格路径下的编译阻断与索引崩溃；业务界面保留友好中文，物理层保持纯英文 ASCII。
- **长耗时重工序空闲看门狗与断点续跑 (Idle Watchdog & Continuation)**：
  对工序 06（设计）与工序 07（研发）等复杂长耗时工序彻底移除单一死板的短硬超时限制。仅在无标准输出且无文件变动超阈值时判定假死；重工序生命周期上限放宽至 7200 秒（2 小时）；断点唤醒时自动扫描已完工资产，精准注入断点上下文续跑。

## 📊 经营战略驾驶舱 (Strategic Executive Cockpit)

ModuFlow 提供专为创始人与业务负责人打造的 **6 大核心板块战略驾驶舱**：

1. **经营总览 (Overview)**：累计实际支出、累计实际回款、净现金流、待办审批数，直观呈现经营底牌。
2. **矩阵产品看板 (Portfolio)**：全矩阵产品投资回报率 (ROI) 排行榜、战略定位（获客/变现）与健康度矩阵。
3. **财务账本 (Financial Ledger)**：收付实现制现金流 vs 权责发生制收支对比、分工序预算消耗分析。
4. **增长获客 (Marketing)**：付费获客、自然裂变与渠道合作表现对比，eCAC 熔断线监控。
5. **数据运营 (Operations)**：DAU、D1/D7/D30 留存衰减曲线、LTV/CAC 核心比率与用户流失预警。
6. **决策与审批中心 (Decision Center)**：
   - **一、经营风险预警**：待处理风险置顶直达操作，已处置记录温和归档；
   - **二、AI 辅助调配建议与审批**：跨产品预算调拨方案、推导依据与数据支撑；
   - **三、重大产研关口待办池**：一页纸关口确认单审查，核对合规与回滚预案后放行。
